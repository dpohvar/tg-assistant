# Роли и команды v1

Обновлено: 2026-10-07. Актуальная матрица заменяет прежние ограничения в исторических разделах discussion.md.

## Роли

Роли назначаются отдельно для каждого дочернего бота; права наследуются user → manager → admin → owner. Owner — отдельный статус владельца, не назначаемый через /set_user.

| Роль | Права |
|---|---|
| user | Общение в ЛС и задачи текущего личного диалога |
| manager | Все права user, подключение групп, управление задачами в группах |
| admin | Все права manager и все команды своего бота, кроме назначения/снятия admin и изменения владельца |
| owner | Все права своего бота, назначение admin и передача владения |

Admin не изменяет себя, других admin или owner через команды ролей. Роль Telegram-администратора группы не означает роль приложения. Права не дают прямого доступа к чужой истории ЛС; границы агентских инструментов сохраняются.

Владелец сервиса определяется userId в конфигурации. Только он пользуется мастер-ботом; роли дочерних ботов такого доступа не дают. По умолчанию он владелец нового бота.

## Мастер-бот: только ЛС владельца сервиса

| Команда | Доступ |
|---|---|
| /newbot TOKEN [OWNER_ID] | Владелец сервиса |
| /bots | Владелец сервиса |
| /set_owner @BotName USER_ID | Владелец сервиса |
| /delete_bot @BotName | Владелец сервиса; сведения и полные команды удаления |
| /delete_bot @BotName BOT_ID | Владелец сервиса; удалить подключение и данные, оставить wiki/Git |
| /delete_bot @BotName BOT_ID all | Владелец сервиса; удалить все данные |

Мастер не использует агента. /set_user и /remove_user выполняются в ЛС дочернему боту; прежний вариант делегирования команд через мастер отменён его исключительным доступом владельца сервиса.

| Команда / действие | Доступ |
|---|---|
| Сообщение в ЛС боту, включая файл | user, manager, admin, owner |
| /tasks [FROM-TO] | user и выше, текущий личный диалог |
| /task TASK_ID | user и выше, текущий личный диалог |
| /retry_task TASK_ID | user и выше, текущий личный диалог |
| /cancel_task TASK_ID | user и выше, текущий личный диалог |
| /get_model [agentId или default] | admin, owner |
| /set_model MODEL [agentId или default] | admin, owner |

| /set_rules [force] | admin, owner; процедура reply на команду/файл сохраняется, автор проверяется по текущим полномочиям |
| /users [FROM-TO] | admin, owner |
| /set_user USER_ID [role] | admin — user/manager; owner — также admin |

| /chats [FROM-TO] | admin, owner |
| /leave_chat CHAT_ID | admin, owner |
| /stop_agent AGENT_ID | admin, owner |
| /transfer_owner USER_ID | Только owner |
| /git_setup [branch [remoteUrl [token]]] | admin, owner |
| /git_changes | admin, owner |
| /git_sync сообщение коммита | admin, owner |
| /ls [директория] | admin, owner |
| /cat путь | admin, owner |
| /download путь | admin, owner |

Неавторизованные ЛС игнорируются, включая /start. Административные команды обрабатывает контроллер без запуска агента. Автоматический отчёт ошибок очистки направляется именно owner; ручная команда отвечает вызвавшему её admin/owner.

## Подключённая группа

| Команда / действие | Доступ |
|---|---|
| Обращение к агенту по правилам триггеров | Все участники |
| Добавление бота в группу, нефорумную супергруппу или канал | manager, admin, owner |
| /tasks [FROM-TO] | manager, admin, owner |
| /task TASK_ID | manager, admin, owner |
| /retry_task TASK_ID | manager, admin, owner |
| /cancel_task TASK_ID | manager, admin, owner |
| /leave | admin, owner |

/leave выходит из текущей группы, останавливает агента и удаляет данные диалога: историю, контекст, notes, очередь, задачи/срабатывания, состояния кнопок. Общие постоянные файлы/wiki и Git сохраняются. Повторное подключение — с нуля.

/stop_agent из ЛС действует на выбранного агента: для группы — тот же выход и очистка; для ЛС — удаление данных диалога и остановка, роль сохраняется, новое сообщение авторизованного пользователя создаёт агента заново. Ответ явно сообщает об удалении данных.

/pause_agent, /pause_bot, /disable_bot, /enable_bot в v1 отсутствуют.

Каналы и супергруппы пассивны, команды в них не выполняются. /leave_chat в ЛС выбранного бота выходит из указанного чата и очищает связанные данные; постоянные файлы сохраняются. Полные правила: [channels-and-discussions.md](channels-and-discussions.md).

Команды /get_model, /set_model, /models доступны admin/owner также в текущей обычной группе. Без agentId выбирается текущий агент; адресный agentId проверяется в пределах бота. default — модель новых агентов, существующие не меняются; смена занятого агента применяется со следующего хода без прерывания. В пассивных чатах команды не обрабатываются.


### Принято: страницы и ответы административных команд — 2026-10-07

- Все команды списков с пагинацией принимают диапазон FROM-TO или одиночную положительную позицию N (например, /agents 5). Это не меняет смысл числовых аргументов других команд: USER_ID, CHAT_ID и другие идентификаторы остаются идентификаторами.
- По умолчанию выдаются позиции 1–10. /users сортируется по userId, /agents — по времени создания от старых к новым, /bots и /chats — по числовому ID. /tasks сохраняет ранее согласованный порядок createdAt/taskId. /agent_messages сохраняет последние 10 записей от новых к старым.
- Ответ показывает фактический диапазон и общее количество, например 11–20 / 83. Диапазон частично за концом возвращает доступную часть; полностью за пределами — «Записей нет». Это текущие списки без снимка/курсора между вызовами.
- Ошибки синтаксиса аргументов возвращаются сразу контроллером, без передачи агенту, выполнения действия или уточняющего диалога.
- Все ответы на команды, включая ошибки и файлы, отправляются как reply на сообщение команды. Для загрузки файлом в ответ на /set_rules или /upload ответ адресуется сообщению с файлом, которое выполнило операцию. Автоматические уведомления не являются ответами на команды и под это правило не подпадают.
