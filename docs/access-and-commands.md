# Роли и команды v1

Обновлено: 2026-10-08. Актуальная матрица заменяет прежние ограничения в исторических разделах discussion.md.

## Роли

Роли назначаются отдельно для каждого дочернего бота; права наследуются user → manager → admin → owner. Owner — отдельный статус владельца, не назначаемый через /set_user.

| Роль | Права |
|---|---|
| user | Общение в ЛС и задачи текущего личного диалога |
| manager | Все права user, подключение групп, управление задачами и текстовыми триггерами в группах |
| admin | Все права manager и все команды своего бота, кроме назначения/снятия admin и изменения владельца |
| owner | Все права своего бота, назначение admin и передача владения |

Admin не изменяет себя, других admin или owner через команды ролей. Роль Telegram-администратора группы не означает роль приложения. Права не дают прямого доступа к чужой истории ЛС; границы агентских инструментов сохраняются.

Владелец сервиса определяется userId в конфигурации. Только он пользуется мастер-ботом; роли дочерних ботов такого доступа не дают. По умолчанию он владелец нового бота.

## Мастер-бот: только ЛС владельца сервиса

| Команда | Доступ |
|---|---|
| /newbot TOKEN [OWNER_ID] | Владелец сервиса |
| /bots | Владелец сервиса |
| /set_owner @BotName USER_ID | Владелец сервиса |
| /delete_bot @BotName | Владелец сервиса; сведения и полные команды удаления |
| /delete_bot @BotName BOT_ID | Владелец сервиса; удалить подключение и данные, оставить wiki/Git |
| /delete_bot @BotName BOT_ID all | Владелец сервиса; удалить все данные |

Мастер не использует агента. /set_user и /remove_user выполняются в ЛС дочернему боту; прежний вариант делегирования команд через мастер отменён его исключительным доступом владельца сервиса.

## Подключённая группа

| Команда / действие | Доступ |
|---|---|
| Обращение к агенту по правилам триггеров | Все участники |
| Добавление бота в группу, нефорумную супергруппу или канал | manager, admin, owner |
| /tasks [FROM-TO] | manager, admin, owner |
| /task TASK_ID | manager, admin, owner |
| /retry_task TASK_ID | manager, admin, owner |
| /cancel_task TASK_ID | manager, admin, owner |
| /leave | admin, owner |
| /clear [AGENT_ID или *] | admin, owner |
| /set_triggers [trigger1 ...] | manager, admin, owner; заменить список текущей группы, без аргументов очистить |
| /triggers | manager, admin, owner; вывести список по одному code-триггеру на строку |

/leave выходит из текущей группы, останавливает агента и удаляет данные диалога: историю, контекст, notes, очередь, задачи/срабатывания, состояния кнопок. Общие постоянные файлы/wiki и Git сохраняются. Повторное подключение — с нуля.

/stop_agent из ЛС действует на выбранного агента: для группы — тот же выход и очистка; для ЛС — удаление данных диалога и остановка, роль сохраняется, новое сообщение авторизованного пользователя создаёт агента заново. Ответ явно сообщает об удалении данных.

/pause_agent, /pause_bot, /disable_bot, /enable_bot в v1 отсутствуют.

Каналы и супергруппы пассивны, команды в них не выполняются. /leave_chat в ЛС выбранного бота выходит из указанного чата и очищает связанные данные; постоянные файлы сохраняются. Полные правила: [channels-and-discussions.md](channels-and-discussions.md).

Команды /get_model, /set_model, /models доступны admin/owner также в текущей обычной группе. Без agentId выбирается текущий агент; адресный agentId проверяется в пределах бота. default — модель новых агентов, существующие не меняются; смена занятого агента применяется со следующего хода без прерывания. В пассивных чатах команды не обрабатываются.


### Принято: страницы и ответы административных команд — 2026-10-07

- Все команды списков с пагинацией принимают диапазон FROM-TO или одиночную положительную позицию N (например, /agents 5). Это не меняет смысл числовых аргументов других команд: USER_ID, CHAT_ID и другие идентификаторы остаются идентификаторами.
- По умолчанию выдаются позиции 1–10. /users сортируется по userId, /agents — по времени создания от старых к новым, /bots и /chats — по числовому ID. /tasks сохраняет ранее согласованный порядок createdAt/taskId. /agent_messages сохраняет последние 10 записей от новых к старым.
- Ответ показывает фактический диапазон и общее количество, например 11–20 / 83. Диапазон частично за концом возвращает доступную часть; полностью за пределами — «Записей нет». Это текущие списки без снимка/курсора между вызовами.
- Ошибки синтаксиса аргументов возвращаются сразу контроллером, без передачи агенту, выполнения действия или уточняющего диалога.
- Все ответы на команды, включая ошибки и файлы, отправляются как reply на сообщение команды. Для загрузки файлом в ответ на /set_rules или /upload ответ адресуется сообщению с файлом, которое выполнило операцию. Автоматические уведомления не являются ответами на команды и под это правило не подпадают.


Уточнение /tasks (2026-10-08): текстовый reply с заголовком `FROM-TO / TOTAL`. Для каждой задачи отдельный блок: моноширинный taskId, затем дата at либо cron с timezone курсивом; следующая строка — непустое description жирным; затем непустая полная инструкция text блоком pre. Форматирование через Telegram entities, без разбора инструкции как разметки. Длинная выдача обрезается с сохранением валидных UTF-16 offsets и пометкой [обрезано]. Агентский инструмент tasks по-прежнему скрывает text без явного запроса taskIds.


Строгая проверка reply для /set_rules и /upload: цитируемое сообщение должно находиться в текущем чате, быть отправлено текущим пользователем и не иметь edit_date. Проверка применяется в обоих направлениях: файл → команда и команда → файл. Чужое, отредактированное или находящееся в другом чате сообщение даёт явную текстовую ошибку reply; скачивания/записи/смены правил не происходит. Файл в ответ на распознаваемую, но недопустимую команду не передаётся агенту. Проверка использует Telegram reply_to_message без состояния приглашения.


### Единый разбор аргументов команд

Вне блоков code/pre пробельные символы разделяют аргументы. Каждый блок code или pre — один аргумент с точным сохранением содержимого; его границы разделяют аргументы даже без пробела. Другое форматирование (bold, italic, ссылки с заданным текстом и т.д.) вызывает ошибку до выполнения команды. Автоматические Telegram entities URL, mention, bot_command и прочие лексические метки не являются форматированием и не меняют разбор.

Все команды, включая мастер-бота и исходную команду при загрузке ответом, используют этот парсер. /edit принимает путь (text/code) и обязательный pre-блок. Остальные структурные команды принимают text/code, не pre. /git_sync соединяет текстовые аргументы пробелом; один code/pre сохраняет точные пробелы и переносы. Количество аргументов проверяется до выполнения действия.

Формат /agents: заголовок FROM-TO / TOTAL; строка — agentId (code), chatType (italic), @username при наличии иначе name, для неперсональных чатов chatId (italic). В ЛС chatId не выводится.

## Очистка контекста и текстовые триггеры

/clear без аргументов действует на текущего существующего агента; AGENT_ID выбирается только внутри этого бота; * выбирает всех его агентов. Запрос не создаёт агента. Свободный агент очищается сразу, занятый — после завершения root, фоновых субагентов и начатых инструментов. Очередь удерживается до удаления старой сессии, затем продолжается с актуальными developerInstructions. agentId, модель, история, notes, задачи, wiki и очередь сохраняются. Запрос очистки хранится в БД и восстанавливается после перезапуска; RAM-очередь по-прежнему не восстанавливается. Повторная команда во время ожидания не создаёт вторую очистку. Ошибка удаления сохраняет запрос и удержание очереди; контроллер сообщает, как повторить /clear. Принудительного прерывания в этой команде нет.

Триггеры отдельны для каждой обычной подключённой группы; по умолчанию []. До 200 строк, каждая 2–50 Unicode code points без переносов строки. Команда использует общий парсер: пробелы разделяют аргументы, code сохраняет фразу с пробелами. Список заменяется атомарно после проверки; повторы без учёта регистра удаляются. /triggers выводит code entities; длинный список делится на несколько reply-сообщений.

Поиск буквальный, без учёта регистра, с проверкой отсутствия Unicode-буквы непосредственно слева и справа. Цифры/подчёркивания/пунктуация допустимы на границе. Внутренние пробелы значимы; ё и е различаются. Проверяются text/caption нового сообщения, не вложенная цитата. Дополнительные триггеры не применяются к автоматически пересланным публикациям. Редактирование не активирует агента заново. Совпадение активирует агент и обновляет громкий режим так же, как упоминание; общие лимиты очереди и альбомов сохраняются. Служебные команды обрабатываются до поиска триггеров.
