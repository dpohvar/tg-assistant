## Найденные несоответствия реализации — исправлены

1. **edit только permits отклоняется.** Контракт разрешает отдельную замену синтетических разрешений, но messages/actions.mjs возвращает invalid_argument без изменяемого Telegram-компонента. Воспроизведено прямым вызовом edit({messageId:7,permits:{"*":[]}}) с известным исходным сообщением. Исправление: отдельная проверенная запись permits без Telegram-вызова.
2. **При замене media не сохраняется прежняя подпись.** Контракт требует подставить caption и caption_entities, когда новая подпись не задана. Воспроизведено заменой photo у сообщения с caption: в отправленном InputMedia caption отсутствует. Также отсутствует явный отказ противоречащим верхнему caption и media.caption. Нужны регрессии отсутствующей/пустой/новой подписи и конфликта.
3. **defaultModel из config игнорируется при регистрации бота.** loadConfig принимает поле, но createMaster/registerBot не передают его в INSERT, поэтому срабатывает SQL-default gpt-6.1-sol. Воспроизведено на временной БД с configured-model. /set_model ... default работает отдельно и был принят пользователем. Исправление не должно менять уже настроенных ботов.
4. **Массивы в схемах инструментов недостаточно описаны.** file_sources/media/entities/caption_entities/reaction имеют type:array без items. В native code-mode наблюдалось описание Array<string> и попытка file_sources:["325"], хотя контроллер ожидает объекты. Нужно задать object items и точные поля provenance; для InputMedia/entities/reactions разрешить нативные объектные элементы. Обновлённые подсказки не заменяют правильную схему.

Все четыре пункта исправлены 2026-10-08. Регрессии сначала воспроизвели четыре отказа, после исправления проходят. permits-only проверен без Telegram-вызова, с отказом устаревшего scope и ошибкой записи. Замена media проверена для сохранённой, новой и пустой подписи, а также конфликтующих параметров. defaultModel передаётся при регистрации через мастер и initialBots; проверено наследование новым агентом без изменения существующей модели. Все массивы динамических инструментов имеют items; file_sources описан объектами с обязательными messageId/fileId. Проверка схем автоматическая; фактическое следование модели новым схемам требует живого обращения.

Полный прогон: Windows 142 проверки, 138 passed / 4 Linux-only skipped; Alpine 142 passed. После дополнительного утверждения наследования модели и уточнения описания edit повторно пройдены профильные master/Codex тесты в Alpine и master в Windows.
