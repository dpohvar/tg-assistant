# Проверка Alpine через Docker

Дата: 2026-10-07. Проверки без авторизации и ограниченный набор живых проверок завершены.

## Окружение

- Alpine 3.24.2, образ `alpine:3.24.2`, digest `sha256:294b683cb724975bec92580e1e685676bd4b50bda910ddb8c51d4cabeaec77e6`.
- Codex CLI 0.159.3, Linux x86_64 musl; Node.js 24.18.1.
- Ядро Docker Desktop: `6.18.40.1-microsoft-standard-WSL2`. Это проверка Alpine userspace, не собственного ядра будущего сервера.
- Контейнер `tg-assistant-alpine-check`, пользователь `probe` (uid 1000), без privileged и без монтирования каталогов хоста.
- SSH доступен только на `127.0.0.1:2227`, public-key-only, root login запрещён. Ключ и known_hosts в игнорируемой `.runtime-check/alpine/`.
- Источник Dockerfile: `tools/alpine-check/Dockerfile`. Контекст сборки — отдельная временная директория с musl vendor и публичным ключом; `.dockerignore` разрешает только Dockerfile, vendor и authorized_keys. Авторизация не включена в образ.

## Песочница

Стандартный seccomp Docker блокирует создание вложенного namespace: `bwrap: No permissions to create a new namespace`. Первоначальный контейнер остановлен и сохранён как `tg-assistant-alpine-check-default`.

Проверочный контейнер запущен с внешним `--security-opt seccomp=unconfined`. При этом профиль Codex остался прежним: `approval_policy=never`, `:minimal=read`, директория бота RW, `.temp` deny, `.temp/a1` RW, network disabled. Это настройка тестового Docker, не требование ослабить профиль агента в приложении.

Проверено настоящим `codex sandbox`, без обращения к модели:

- вики и `.temp/a1` доступны на чтение/запись;
- `.temp/a2` и синтетический секрет контроллера недоступны (ENOENT);
- создание сетевого socket из песочницы отвергнуто (EPERM).

## Результаты без авторизации

- `save-image-probe.test.mjs`: 1 тест прошёл (несколько сценариев назначения, регистрации и границ доступа).
- Адаптер Croner: 38/38 тестов прошли, включая DST, таймеры и одноразовое событие.
- App-server запускается; вызов каталога моделей выполнен. Это не доказательство успешного inference или авторизации.
- SSH с выделенным ключом проверен: uid 1000.

Артефакты находятся в контейнере `/home/probe/runtime/results` и локально `.runtime-check/alpine/results`. Секреты в документацию не сохраняются.

## Живые проверки после авторизации

Пользователь авторизовался через SSH с `CODEX_HOME=/home/probe/runtime/control-home codex login --device-auth`; CLI подтвердил `Logged in using ChatGPT`. Авторизация хоста не копировалась. Все нижеперечисленные режимы завершились без ошибки harness.

- `sandbox`: живой агент выполнил проверку доступа под тем же профилем и записал файл в свою `.temp/a1`.
- `web`: встроенный live web search работает при запрещённой сети shell.
- `image-export-subagent`: один нативный субагент сгенерировал изображение штатным инструментом, сохранил через динамический `save_image` в `.temp/a1/generated` и `wiki/images`. Генерация и сохранение выполнены одним JavaScript вызовом без вывода base64.
- Во время генерации основной агент принял steer: отправлено 14:24:13.843Z, ответ `STEER_ACK` получен 14:24:17.259Z (3.416 секунды). Генерация завершилась позже, в 14:24:30.351Z. Затем основной агент получил результат субагента и закончил работу.
- `instructions`: правило `CHECK_ALPHA` сохранилось после сжатия и resume. Попытка заменить его на `CHECK_BETA` через resume не сработала — ответ остался с `CHECK_ALPHA`.
- `instructions-fresh`: новая сессия получила новое правило `CHECK_BETA`, включая после сжатия. Принятое решение пересоздавать сессию при смене правил подтверждено.
- `model-switch`, `model-resume`: переключение `gpt-6.1-sol` → `gpt-6-sol` сохранило тестовую память и инструкцию, в том числе после сжатия и перезапуска app-server. Уже запущенный субагент остался на старой модели, новый получил текущую модель родителя.
- `delete-active`: удаление дерева сессий при работающем субагенте остановило его; ожидаемый файл-маркер не появился после периода наблюдения, логи удалённых сессий не восстановились.
- `delete-verify`: после нового запуска app-server удалённые сессии недоступны для resume, их rollout-файлы отсутствуют.

Ограничения: Docker использует ядро WSL2; отдельное ядро настоящего сервера не проверено. Проверена одна пара моделей и один небольшой пример генерации, не все модели/нагрузки. Это стенд существующих прототипов, не интеграционный тест ещё не написанного приложения. Прямую генерацию без субагента в Alpine повторно не проверяли. Авторизация остаётся только в выделенном controller home контейнера для следующих проверок; после авторизации снимки образа не создавались.

Windows OpenSSH первоначально отклонил тестовый ключ из-за унаследованных ACL. ACL файла `.runtime-check/alpine/ssh_key` исправлен: доступ только текущему пользователю. Вход отдельно проверен через `C:\Windows\System32\OpenSSH\ssh.exe`.
