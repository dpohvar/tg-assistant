# Vault, сеть агента и spoiler-аргументы — план реализации

> Для исполнителя: использовать superpowers:executing-plans; выполнять задачи последовательно с проверками.

**Цель:** дать агентам бота доступ к секретам через программный вызов инструмента и разрешить сетевые команды в существующей файловой песочнице.

**Архитектура:** контроллер хранит секреты в SQLite, отдельно по botId. vault_get возвращает строку для использования внутри code-mode. Агенту запрещено раскрывать её пользователям; значение допускается в закрытых серверных записях вызовов. Отдельного исполнителя команд и постоянных соединений не создаём.

**Стек:** существующие Node.js, SQLite, Codex app-server и shell-инструменты; без новых зависимостей.

## Принятые требования

- Администратор сервера имеет доступ к БД и служебным логам. Шифрование БД не входит в задачу.
- Секрет может присутствовать в аргументах shell-вызова и закрытых логах сессии. Это не равно разрешению публиковать его пользователям.
- Агент получает и использует значение в одном JS-вызове, не печатает его. Перед выводом результатов проверяет отсутствие секретов. Гарантия от намеренного раскрытия кодом не заявляется.
- Разрешается сеть shell; файловая песочница сохраняется.
- spoiler считается одним аргументом, как code: внутренние пробелы сохраняются, границы отделяют соседние аргументы. pre остаётся отдельным типом для /edit и /git sync.

## Предлагаемый контракт (нуждается в принятии)

| Команда | Результат | Доступ |
|---|---|---|
| /vault или /vault list | Список имён, без значений; пустое хранилище явно обозначено | admin/owner, ЛС дочернему боту |
| /vault set NAME TOKEN | Создать или заменить значение | admin/owner, ЛС |
| /vault delete NAME | Удалить; явно сообщить, если имени нет | admin/owner, ЛС |

NAME: ASCII [A-Za-z][A-Za-z0-9_-]{0,63}, регистр значим. TOKEN: непустой, до 16384 UTF-8 байт; сохраняется точно, без trim. Пробелы внутри значения через code/spoiler. pre для vault не принимается. Инструмент vault_get({name}) возвращает {value:string} либо стандартные error/description на английском. Все агенты этого бота имеют доступ ко всем его секретам; botId определяется scope, не аргументами агента. Нет чтения значения через пользовательскую команду и межботового доступа. Домены не добавляем: после получения строки они не обеспечивают ограничения адресата.

Команда set не сохраняется в истории, не отправляется агенту. Удаление исходной команды и ответ с reply выполняются по существующей механике /bot add; исключение из общего reply-правила не вводится. Ответы и ошибки не повторяют значение секрета. Spoiler лишь визуально скрывает текст, не шифрует его. Удаление бота удаляет его vault независимо от сохранения вики; удаление чата/агента и /git setup секреты не удаляют.

## Карта файлов

- src/storage/migrations/<следующий номер>.sql: таблица vault(botId,name,value), PK(botId,name), FK с корректным удалением.
- src/storage/database.mjs или отдельный src/storage/vault.mjs: get/list/upsert/delete без вывода значений в ошибки.
- src/commands/vault.mjs: команды, роль, ЛС, безопасные ответы.
- src/commands/router.mjs, contract.mjs, help.mjs: регистрация и помощь.
- src/commands/arguments.mjs: spoiler -> семантика code.
- src/controller.mjs: vault_get через текущий scope, отсутствие секретных команд в сохранённой истории.
- src/codex/threads.mjs: схема инструмента, developerInstructions, network enabled.
- docs/commands.md, agent-contract.md, operations.md: согласованный контракт и модель доверия.
- test/integration/: соответствующие тесты; test/live/: синтетическая проверка на Alpine без настоящих токенов.
