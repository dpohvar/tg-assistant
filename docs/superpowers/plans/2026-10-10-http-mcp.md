# HTTP MCP Implementation Plan

**Execution status (2026-10-10):** implementation complete. Transport/config/storage/commands/runtime refresh and review fixes are committed in feat/websocket-mcp. The original checklist below is retained as the planning record; final delivered files and verification are recorded in [../../websocket-mcp-check-results.md](../../websocket-mcp-check-results.md). Live probes are consolidated in test/live/websocket-mcp.mjs, websocket-tls.mjs and mcp-failure.mjs. No merge/push is included in this task.


> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for native execution, or superpowers:subagent-driven-development if explicitly selected. Steps use checkbox syntax for tracking.

**Goal:** admin настраивает HTTP MCP бота родным TOML-фрагментом; все агенты этого бота используют его нативные инструменты Codex.

**Architecture:** SQLite хранит подключения и revision; конфигурация передаётся изолированным App Server. Изменения применяются после полного завершения работы через resume того же threadId, без очистки контекста. Совместимость этого пути подтверждается до продуктового кода.

**Tech Stack:** Node >=24.18.1, node:sqlite, smol-toml 1.9.1, Codex App Server, node:test, Alpine Docker. Версии зависимостей фиксируются в lockfile.

**Spec:** [../../mcp.md](../../mcp.md). План независим от WebSocket и может быть выполнен отдельно.

## Global Constraints

- Только Streamable HTTP; без stdio, OAuth, WebSocket MCP и vault references.
- Admin/owner в ЛС дочернего бота; config принадлежит botId, общий для его агентов.
- Нативные имена TOML Codex; набор разрешённых HTTP полей указан в spec.
- Секреты не в истории/инструкциях/wiki; set reply и best-effort delete original.
- Изоляция от MCP других ботов и общего CODEX_HOME; shell sandbox не меняется.
- Не создавать универсальный mcp_call и не реализовывать собственный MCP протокол.
- Тесты на 0.161.0, если доступна; документировать реально проверенные версии.

## Review Focus

1. Общий config.toml имеет посторонний MCP: ни один агент бота не получает его.
2. TOML ошибка содержит token: пользовательский error не цитирует исходник.
3. Два бота имеют MCP с одинаковым NAME: каждый получает свой URL/credentials/tools.
4. Set/delete во время root/subagent работы: старый процесс не обрывается,
   новый ввод ждёт refresh, контекст сохраняется.
5. OAuth challenge/elicitation или недоступный сервер: bounded test завершается
   безопасной ошибкой, не запускает браузер и не выполняет инструмент.
