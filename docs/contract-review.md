# Сверка документации v1

Дата: 2026-10-07. Проверены agent-contract.md, message-events.md, access-and-commands.md, channels-and-discussions.md и история discussion.md. Это сверка согласованных решений; работающая интеграция не проверялась.

## Результат

Основная модель v1 согласована. Дочерний бот — граница доступа: общая wiki и правила, агенты личных диалогов и обычных групп, пассивные каналы/нефорумные супергруппы. Чужие ЛС закрыты. Очередь событий в памяти, расписание в БД. Пользовательские MCP и маршрутизация исключены; встроенный веб-поиск — live для всех агентов.

## Исправленные расхождения

- Убраны устаревшие ограничения send/edit/delete/react текущим чатом: допускается адресная работа в подключённых пассивных чатах, но не в чужом чате с агентом.
- Чтение истории и файлов распространено на разрешённые group/supergroup/channel. Для обнаружения пассивных чатов используются chats()/chat_info(), а не только agents().
- Команды ролей перенесены из старого описания мастер-бота в ЛС дочернему боту. Права /set_rules приведены к owner/admin, включая проверку файла-ответа.
- Передача владения относится к конкретному дочернему боту в сервисе, а не к сервису целиком или владению через BotFather.
- Восстановление после остановки и календарные правила Croner больше не обозначаются как непринятые решения. Проверки их реализации остаются необходимыми.
- Старый список открытых вопросов заменён этой сверкой. discussion.md явно обозначен как история, а не актуальная спецификация.

## Что ещё нужно согласовать в контракте

1. **Аргументы forward/copy — закрыто.** Приняты chatId назначения и fromChatId источника; оба необязательны и независимо означают текущий чат при отсутствии. Примеры обновлены. forward не принимает кнопки/reply; copy одного сообщения принимает оба.
2. **Завершённые схемы send/edit по типам.** Семантика согласована, но пока нет полной таблицы обязательных полей, поддерживаемых параметров и сочетаний заменяемых компонентов. Её нужно подготовить перед реализацией инструментов.
3. **Повторное использование исходящих файлов — закрыто.** Полный ответ Message сохраняется; одиночный copy при сохранённом исходнике даёт восстановленную запись с отметкой. Для пакетов без надёжного соответствия записи не выдумываются: read/download результата могут быть недоступны. Файл можно использовать через доступный исходник и file_sources.
4. **Обычные страницы команд — закрыто.** Приняты страницы по 10, одиночные позиции, порядок списков, немедленные ошибки синтаксиса и reply для всех ответов на команды. Полные правила в access-and-commands.md.

Эти пункты — уточнение формата и хранения, а не новые функции v1.

## Что требует проверки интеграции

- Сохранение developerInstructions/AGENTS.md при compaction и resume, применение новых правил между ходами и принудительная смена.
- Приём steer во время ожидания субагентов и генерации изображения; достоверные признаки занятости основного агента и возможность открыть очередь.
- Генерация изображений через выбранный App Server с фактической ChatGPT-подпиской: доступность, события, файл результата, отправка в Telegram. Пока не подтверждено live-тестом.
- Работа встроенного web search live с выбранной авторизацией.
- Песочница: отсутствие доступа к секретам, чужим ЛС и временным файлам других агентов при разрешённой общей RW wiki и штатных файловых инструментах.
- Croner: согласованные DST/календарные правила, одноразовые даты, учёт пропущенных срабатываний и восстановление состояний планировщика.
- Реальные Telegram-сценарии rich, callback, реакции, комментарии и multipart-вложения. Отключение rich-кнопок при пересылке проверено пользователем; поведение copy отдельно не подтверждено.

## Принятые ограничения, которые не нужно обсуждать заново

- История — 30 дней от первого получения, межагентный журнал — 7 дней, временные файлы — 24 часа по mtime. Ежедневная очистка допускает дополнительный интервал до суток.
- Очередь — 10 ожидающих событий чата, включая кнопки и edits; планировщик и межагентные сообщения вне этого лимита. Межагентная очередь не ограничена в v1.
- Громкий режим — 2 минуты/10 сообщений; собранный альбом считается одним событием. Сборка альбома: 1 секунда тишины, предел 3 секунды от первого элемента.
- Общая wiki без прав разделов, блокировок параллельного редактирования и pull/fetch в агентских Git-инструментах. Административный /git_setup имеет отдельно согласованную разрушительную синхронизацию.
- Уведомления и административные команды текстовые, длинная служебная выдача обрезается с отметкой. Исключения файловых команд сохраняются.
- Повтор задачи после сбоя может повторить уже выполненное действие; завершение задач привязано к основному ходу, complete_tasks отложен.
- Форумы и inline-вызов бота исключены; пассивные чаты не имеют агента, команд и обработки кнопок.

## Дополнение: уточнения edit — 2026-10-07

При совместном изменении permits и rich/клавиатуры разрешения сохраняются после подтверждённого изменения хотя бы одного из этих компонентов; при частичном сбое исправление поручается агенту. Дополнительная блокировка callback не вводится. При отсутствии исходной записи и необходимых данных edit возвращает понятную ошибку; старый reply не восстанавливает запись автоматически. Основная семантика send/edit уже согласована, оставшаяся таблица полей уточняет схемы отдельных типов.


## Авторизация v1 — закрыто, 2026-10-07

Владелец сервера авторизуется через Codex CLI; все боты и агенты используют один аккаунт. Подключение отдельных пользовательских аккаунтов и передача Codex-токенов исключены из v1. Проверки интеграции выполняются именно с этой авторизацией.
