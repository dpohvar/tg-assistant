# Проверка активных WebSocket и HTTP MCP

2026-10-10. Реализация в `feat/websocket-mcp`. Проверки выполнены локально
на Windows и в Docker Alpine под пользователем probe.

## Автоматические проверки

Полный `npm test` включает транспорт, файлы, интеграцию контроллера,
команды и роли, MCP TOML/хранение/изоляцию, обновление конфигурации и миграции.
Последний полный прогон: **211 тестов**. Windows: **203 passed, 8 skipped**;
Alpine (Node 24.18.1): **208 passed, 3 skipped**. Ошибок и отмен нет.
Пропуски относятся к проверкам, требующим другой ОС или явно заданного
окружения; проверки symlink выполнены на Alpine.
Syntax check всех 59 модулей src и `git diff --check` проходят.

Проверены FIFO, сборка фреймов в целое сообщение, UTF-8 и граница 1 MiB,
10 MiB на сообщение, бинарное хранилище до 20 MiB, skipped при переполнении,
удалённый до чтения файл, границы файловой системы и symlink на Alpine,
10 записей с учётом закрытых, часовой TTL с fake clock и очистка при запуске.
Закрытие/удаление/shutdown во время handshake завершают ожидающий ws_open.

Для MCP проверены поля TOML, маскирование секретов, доступ admin/owner,
удаление чувствительной команды, разделение по botId и каскадное удаление.
Обновление ждёт основной ход и субагентов и удерживает новую очередь.
Остановка/удаление во время чтения конфигурации отменяют запуск; отдельный
тест проверяет закрытие настоящего preflight-процесса.
Миграция схемы 9 → 10 сохраняет vault; старые миграции также проходят.

Финальная независимая проверка кода: замечания исправлены, подтверждённых
Important/Critical после повторной проверки нет.

## Живой Codex на Alpine

`test/live/websocket-mcp.mjs` запускался с настоящим Codex App Server,
авторизацией CLI и файловым профилем tg-agent. Telegram transport заменён
локальной записью ответов; реальный Telegram этим тестом не проверялся.
WebSocket и HTTP MCP — настоящие локальные серверы с синтетическими секретами.

Успешно на **0.159.3** и **0.161.0**; после исправлений повторно на **0.161.0**:

- Агент собирает URL с vault_get, сервер подтверждает авторизацию.
- Отложенное websocket_ready запускает ход без сообщения из Telegram.
- Агент извлекает текст и бинарный файл и отправляет оба обратно.
- Нативный MCP echo_v1 вызывается с нужным заголовком авторизации.
- `/mcp set` меняет сервер/tools; следующий ход вызывает echo_v2.
- threadId и запомненный маркер сохраняются после обновления MCP.
- Существующий WebSocket живёт через обновление MCP без нового подключения.
- `/ws close/delete` закрывают/удаляют запись через обычный обработчик команд.
- Генерация изображений доступна; изображения в этой проверке не генерировались.
- Ошибок контроллера нет; синтетические токены не появляются в ответах чата.

Проверка `test/live/mcp-failure.mjs` на 0.161.0 без хода модели:
отключённое подключение проверяется временно включённым, настройка не меняется;
HTTP 401 возвращает безопасную ошибку без URL-секретов. MCP tools/call не вызывается.

В `test/live/websocket-tls.mjs` проверен настоящий wss echo и Authorization
header с собственным тестовым сертификатом, доверенным через NODE_EXTRA_CA_CERTS.
Проверка TLS не отключалась.

## Важные результаты исследования

Codex объединяет process override mcp_servers с настройками общего home.
Поэтому одного нового TOML-объекта недостаточно: унаследованные подключения
явно отключаются, подключения бота получают собственные имена. Конфликт
локального имени с namespace контроллера отклоняется.

Нативные MCP по умолчанию могли требовать approval, которое невозможно
при approval_policy=never. Администраторское подключение получает
default_tools_approval_mode=approve; при этом enabled_tools/disabled_tools
сохраняют ограничение набора инструментов.

Записи WebSocket находятся только в памяти. Перезапуск теряет буферы и
не восстанавливает соединения. Shell-процессы и их прежний механизм
завершения не менялись. OAuth/stdio/WebSocket MCP не поддерживаются.
