# Управление агентами и структурированные команды — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Не делегировать работу без отдельного разрешения.

**Goal:** Поддержать включаемых агентов в группах и нефорумных супергруппах и заменить команды согласованным структурированным набором без потери существующей БД.

**Architecture:** Подключённый чат, желаемая включённость и текущая работа агента — разные состояния. Контроллер сохраняет историю независимо от включённости; остановка блокирует новый вход, дожидается всей начатой работы и удаляет только контекст. Планировщик сохраняет пропуски, а маршрутизатор разбирает команды в явные действия с проверкой роли и цели до побочных эффектов.

**Tech Stack:** Node.js >=24.18.1, ESM, node:sqlite, Croner 10.0.1, существующий адаптер Temporal, Telegram Bot API, Codex app-server. Отладка Windows, сервер Alpine Linux.

**Spec:** [../../commands.md](../../commands.md). Это целевой контракт; при исполнении читать оба документа.

## Глобальные ограничения

- Новые группы/нефорумные супергруппы — агент выключен; существующие агенты после обновления включены. Авторизованные новые ЛС могут включаться автоматически, явный stop не отменяется обычным сообщением.
- Форумные группы запрещены: выход и удаление данных диалога, включая задачи и заметки. Общая wiki/Git сохраняется. Каналы пассивны.
- Stop сохраняет agentId, модель, заметки, историю, задачи; clear также сохраняет ожидающую очередь. Stop очищает оперативную очередь, сохраняя события задач как пропущенные.
- История 30 дней, межагентная переписка 7 дней, temp по mtime 24 часа; очередь 10 chat-событий и громкий режим 2 минуты/10 сообщений не меняются.
- Старые команды без алиасов. Все ответы reply, ошибки синтаксиса предлагают help раздела. Неавторизованные ЛС игнорируются; права приложения не выводятся из Telegram-администрирования.
- Коммиты/push/развёртывание выполняются только в разрешённом пользователем объёме. Этот этап создаёт план, не изменяет приложение.

## Особое внимание при проверке

1. Stop во время ожидания субагента: новые события не проходят через steer, текущие побочные эффекты завершаются, заметки/задачи остаются.
2. Перезапуск между запросом stop и удалением сессии: выключенность сохраняется, контекст не возобновляется сам.
3. Адресная команда из чужого ЛС/группы: проверка botId и роли до изменения/показа данных; закрытые команды не раскрываются справкой.
4. Два Telegram-события миграции группы: перенос ровно один раз, сохранены история и ссылки на файлы, нет конфликта ID сообщений.
5. Stop при queued cron и успешном завершении предыдущего firing: пропуски не исчезают и не дублируются; штатная остановка не порождает уведомление о сбое.

в `C:/PROJECTS/tg-assistant`. Не смешивать изменения двух worktree автоматически.
Каждый шаг: сначала падающие регрессии, затем минимальная реализация и успешные
целевые тесты. Полный набор запускать после интеграции, а не после каждой строки.
После пользовательского выбора исполнения работать последовательно в текущей
сессии; не запускать приложение и не менять живую БД на этапе подготовки плана.
