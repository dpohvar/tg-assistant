# Inline agent and widget views — итоговая сверка

Ветка: `feat/inline-agent-views`, база `8468767d139df48b50e52680b8a74ebeddabd7aa`. Изменения находятся в отдельном worktree. Пользователь разрешил коммит и публикацию в `main` после завершения проверок. Обновление рабочего сервиса не входит в задачу.

Статус: реализация, согласованные живые проверки, самостоятельный review и итоговые Windows/Alpine gates завершены. Реализация подготовлена к публикации в `main`; рабочий сервис не обновлялся.

## Результат

- Inline-поручение поступает существующему личному агенту через барабан. Порог отправки2000мс, ожидание5000мс, страницы6,6,20,20…; пользователь сохранил эти значения и отказался от дополнительного замера после смены компоновки.
- Первая строка использует аватарку дочернего бота, иначе мастер-бота, иначе обычный article. Кэш профилей —5минут, отдельно для каждого дочернего токена. Выбор служебной карточки отправляет только `✖️`.
- Запрос/результаты живут в RAM не более часа; новый запрос заменяет старый. Только явный `set_inline_results` завершает ожидание, включая фоновые продолжения. Кнопки записываются перед выдачей страницы; принятое очередью нажатие считается доставленным.
- Поддержаны19 обычных native-вариантов и rich-содержимое. Games и invoices исключены по решению пользователя. Фото по-прежнему перенесены в конец и начинаются с отдельной страницы для случая отсутствующей аватарки. Прямые inline uploads запрещены; агент использует подтверждённый буфер. Cached audio требует сохранённого названия при загрузке.
- Один widget имеет общее состояние, очередь и таймеры и0..N view. `render(state,view)` получает замороженный снимок. Новые инструменты:create/update/list/get/delete widget, set/delete view, widget_event. Остановка аварийная; update восстанавливает stopped widget, старые события после остановки не воспроизводятся.
- Миграции14→15→16 сохраняют прежние виджеты и преобразуют отображения/события транзакционно. Компиляция вынесена из постоянного widget runtime во временный sandbox; прежние ограничения памяти и heartbeat сохранены.

Контракты: [inline](../inline.md), [widgets](../widgets.md), [agent tools](../agent-contract.md), [обновление и восстановление](../operations.md).

## Самостоятельный review RF1–RF5

| Фокус | Проверено |
| --- | --- |
|RF1:неопределённая доставка|Publication receipts сохраняют неопределённость, восстановление не повторяет эффект и не перезаписывает старой проекцией новые наблюдения; ошибка snapshot/registry не вызывает автоматический resend|
|RF2:замена view|Барьер публикации и отсечение кнопок; callback сверяется с текущей клавиатурой и view ID; reply/reaction сохраняют непрерывность binding, detach её разрывает|
|RF3:владение/истечение|Проверка владельца и действующего view независимо от snapshot; widget callbacks не перехватываются старым action btnId; конфликт содержит owner/widget/view IDs|
|RF4:миграция|Преобразование в транзакции до runtime, прежние widget IDs/state/callback payload; stopped backlog удаляется. Реальный Wordle не редактировался|
|RF5:поздняя работа|Повторная проверка допуска перед dispatch/steer, отмена pending старого request, синхронная отметка принятия кнопки очередью, отсутствие повторной доставки после этой границы|

Новых проблем по этим пяти фокусам при итоговой сверке не найдено. Ранее найденные сохранение старого форматирования и отсечение чужого view при конфликте исправлены с регрессионными проверками. Review выполнен основным агентом; независимый reviewer не заявляется.

## Границы

- iOS и живой сценарий нескольких агентов/участников в общем канале/группе оставлены непроверенными по прямому решению пользователя; изоляция покрыта автоматическими тестами.
- Точная версия/viewport клиентов не записаны; не установлен универсальный минимальный размер барабана или худшая сетевая задержка. Новый замер высокой компоновки не требуется по решению пользователя.
- В свежей группе callback пришёл, обычные сообщения/reply/reaction не пришли. Это ограниченный прогон, без смены членства/админских прав и без Guest Mode; обещание onReply/onReaction по одному inline ID не даётся.
- Медиаматрица подтверждает проверенные fixtures и варианты, не все комбинации необязательных полей. Group/custom-emoji особенности архива Wordle и таймер Wordle без view не выдаются за отдельные живые проверки; соответствующее базовое поведение покрыто автоматическими тестами.
- Тестовые публикации в неизвестных чатах остаются под управлением пользователя. Контроллер не придумывает их адреса и не удаляет произвольные сообщения. Тестовые poller-процессы остановлены; приватные credentials/manifests/logs остаются в игнорируемом fixture для воспроизводимости.

Для обновления рабочего сервиса нужен отдельный этап:остановка и backup до миграции. Возврат старого кода требует pre-upgrade backup; обратная миграция поверх новой БД не реализуется.

## Публикация

Пользователь отдельно разрешил коммит и push в `main`. Перед коммитом повторный полный Windows-прогон:584 теста,576 pass,8 platform skip,0 fail; проверка wiki и staged diff также прошли. В публикацию входят только `docs/`, `src/` и `test/`; локальные токены, БД, архив Wordle и журналы экспериментов исключены. Рабочий сервис не разворачивается этой задачей.
