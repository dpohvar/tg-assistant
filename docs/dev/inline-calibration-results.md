## Dedicated prefetch page-size experiment

The user requested separate Desktop/Android measurements of automatic loading, initially one article per response, then five. The bounded prefetch runner bypasses the 2-second trigger and all agent work, answers valid cursors immediately, and records unique confirmed pages and rows, pagination requests, failures and quiet time. Rows have the production title-only shape plus continuous ordinals. The 500-page cap was not reached in any recorded sample. Client version and viewport remain unrecorded.

The user watched five one-row items appear successively, with no scrollbar; wheel input could not scroll or load more. Both one-row samples completed their initial five responses within 729/736 ms. The untouched five-row sample completed five pages within 768 ms. All retained a next cursor and had no answer errors, so these stops were not caused by an empty cursor, the probe cap or a recorded failed response.

In the immediate-scroll five-row control, the user supplied the summary of 25 pages / 125 rows; the final answer arrived 34,995 ms after sample creation, and the summary at 44,893 ms. Additional pagination past the untouched 25-row baseline is confirmed. This run combines automatic loading and user scrolling: do not classify all 24 pagination requests as automatic or treat 125 rows as a prefetch threshold.

The Android five-row untouched sample returned two pages / ten rows: one initial response and one pagination request, both successful within 683 ms. Its summary arrived 30,515 ms after creation, with no request for 29,912 ms; the next cursor remained available and the cap was not reached. In the subsequent scrolling control, the user supplied 17 pages / 85 rows, with 16 pagination requests and no errors. The final answer arrived at 36,735 ms and the summary at 53,437 ms. Continuation past the untouched ten-row baseline is confirmed; 85 rows is not an automatic-prefetch threshold. Desktop and Android made different numbers of automatic requests with the same five-row pages in these samples.

The three-row Desktop control returned five pages / 15 rows, all successful within 1,356 ms; its summary recorded 40,038 ms without another request. The user saw all 15 rows and no scrollbar after waiting. The user then replaced the proposed four-row follow-up with a variable-size control: pages of 6, 6, 10, 20, 30, then repeated 30 rows. Its cumulative totals are 6, 12, 22, 42, 72, 102, and so on. The user predicted 12 rows on Android and 22 or 42 on Desktop. The Desktop sample returned four pages / 42 rows (6+6+10+20), all successful within 598 ms. It requested another page after the cumulative 22 rows, then no fifth page: the summary recorded 24,114 ms without a request at elapsed 24,607 ms. The next cursor remained available; no error or cap ended the sequence. This supports an observed stop at 42 rows for this scale, not an exact minimum initial page size.

The Android scale control returned two pages / 12 rows (6+6), with one pagination request and no errors or cap reached. Both answers completed within 331 ms; the summary arrived at 24,011 ms with no request for 23,757 ms. A cursor for the next ten-row page remained available. The observed cumulative stop was therefore 12 on Android, compared with 42 on Desktop. These samples match the user's predictions, while the exact minimum initial page size and behavior on other viewports/versions remain unmeasured.

Five-row pages support continued loading in both tested clients, while one- and three-row pages left the Desktop user unable to scroll. This does not establish the minimum page size, a universal five-request client cap, or the minimum size that suppresses automatic prefetch. The user subsequently accepted prompt pages of 6,6,20,20… with a leading ⬇️ on all three continuing service labels. Prompt sizing resets for a new initial query; sent/working responses remain one row, and terminal Work complete has no arrow. The 2,000/5,000 ms timings remain unchanged. These transport-only controls did not exercise real agent admission or waiting.
