# Master usage implementation verification

The master bot now reports per-bot and combined usage, retained UTC periods and changes relative to an intact previous report. Accounting uses schema 12, stable Telegram bot IDs and transactional cumulative baselines. Removed bot totals remain available. Existing sessions seed their first observation; historical expense is not imported.

## Automated verification

- Windows: 296 tests, 288 passed, 8 skipped, 0 failures.
- Alpine Linux, ordinary `probe` user: 296 tests, 293 passed, 3 skipped, 0 failures.
- Coverage includes schema 11 upgrade and reopen, retained data, transaction rollback, period boundaries, root/child ownership, replay, image duplicates, reset handling, report parsing, provenance, permissions, truncation, renamed/removed bots and deletion help.

The Alpine test copy normalized the Windows checkout's askpass shebang to LF. Git release archives already contain LF; no production Git behavior was changed.

## Live Codex adapter verification

Tests used the production adapter and sandbox settings on Alpine with Codex 0.159.3, isolated SQLite databases and private temporary workspaces. They did not send Telegram messages or alter the running test service's database.

- Full run: root, resume, child and image generation. Recorded 185,566 input tokens, 472 output tokens, one generation and 948,680 generated bytes. The generated file size matched accounting; report parsing round-tripped the exact counters.
- Final smoke after review fixes: root, resume, child, explicit compaction and a subsequent turn. Recorded 129,754 input tokens and 120 output tokens. Replay did not inflate totals; report round-trip passed. Image generation was omitted from this second run because it was covered by the full run.

Owned test sessions and child sessions were cleaned up. These are live adapter checks, not manual Telegram UI acceptance or billing reconciliation. No live check on Codex 0.161.0 was performed.

## Independent review and corrections

The reviewer found two important issues: a genuinely reset cumulative counter could suppress subsequent usage, and an old completion timestamp could remove a reused child baseline. Both were reproduced with failing regressions and corrected. Resets now rebase conservatively only on an observed new turn; stale decreases are ignored. Recent child activity prevents premature cleanup. Image dedup records also expire after seven days without updates to bound retained metadata.

## Deletion help

`/help bot` presents only `/bot delete @BotName`. Its confirmation prompt identifies the bot and owner, explains irreversible history/context loss, and provides code-formatted commands for deleting all files or preserving permanent files. Usage statistics remain. Automated tests cover this behavior.

## Limits

Usage means runtime-reported counters rather than invoice totals. Generation starts include failures; generated bytes measure native output files, not retained storage. No pre-upgrade history, model breakdown or agent breakdown is imported. Report comparisons use Telegram timestamps and may differ slightly from the exact accounting read time. English wiki updates are in the master-bot, storage and architecture articles.
