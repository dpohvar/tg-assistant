# Browse Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, with test-driven-development and one independent whole-change review. The user authorized implementation and starting the test bot; do not pause for a second plan approval. Do not commit, merge or push without authorization.

**Goal:** Implement the agreed `/browse [dir]` rich file browser and start an isolated test-bot controller for manual acceptance.

**Architecture:** A controller-owned service manages one in-memory session per bot/user. Scoped file operations, rich rendering and Telegram/session routing are separate modules. Callback messages provide observed Telegram media IDs for reuse after ephemeral edits, whose responses are only `True`; retain bounded prepared bytes when IDs are unavailable.

**Tech Stack:** Node.js >=24.18.1, existing Telegram transport, BotFiles, native zlib ZIP generation, node:test. No new runtime dependencies.

**Spec:** [Browse design](../browse-design.md).

## Global Constraints

- Preserve existing commands. Admin/owner only; no model turn or enabled-agent requirement. Ordinary and ephemeral routes remain distinct, with no public fallback.
- Three blocks: breadcrumbs; directory/file information; actions + optional document, clipboard and status.
- Text preview: whole file <=2048 bytes, first <=50 lines, native pre block with known language.
- One session per bot/user; new command deletes/replaces its message, carries clipboard/cache and any active operation.
- Confirm deletion and overwrites; directory merges preserve non-conflicting destinations. Clipboard stores a path, not bytes.
- Use 10 entries per page, one-hour idle TTL, max 2000 entries/32 MiB per tree operation or file, 64 MiB prepared cache/session, max image upload 10 MiB. Check roles and paths after async work.

## Review Focus

- Native ephemeral edit returns only True; repeat renders must not invent file IDs or publish staging messages.
- Repeated IDs/stale callbacks and a new browse while work is active must never mutate the wrong object or resurrect an old view.
- Confirmation target changes and upload filename traversal must not allow unintended writes.
- Symlink swaps/protected nested entries and self/descendant copies must not escape scoped file access.
- Full controller routing must consume browse callbacks/uploads before private-message suppression and agent/widget routes.
