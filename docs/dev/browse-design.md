# Интерактивный файловый проводник /browse

Статус: согласованный дизайн, реализованный и принятый пользователем; одобрен коммит и push в `main`. Основа исследования — `origin/main`, `f126542`. [Проверки и граница живой приёмки](browse-verification.md); текущее реализованное поведение описано в [wiki](../commands.md#interactive-file-browser).

## Назначение и границы

Добавить `/browse [dir]`: файловый проводник в одном редактируемом rich-сообщении, которым можно пользоваться на Android без копирования путей. Существующие `/ls`, `/cat`, `/download`, `/upload`, `/mv`, `/rm` и `/edit` сохраняют поведение.

Контроллер выполняет навигацию и операции напрямую, без модельного хода и зависимости от включённого агента. Используются текущие роли и область файлового доступа. В приватном чате ответ обычный; на эфемерную команду в группе ответ и приглашения остаются эфемерными. Публичного fallback при ошибке нет.

## Согласованные требования

### Вход и структура сообщения

- Без `dir` или при отсутствии указанной директории открывается корень файлов бота.
- Блок 1 — хлебные крошки с иконками: `🏠` для Root, `📁` для остальных каталогов, `📄` для текущего файла. У кликабельных сегментов иконка и имя входят в одну ссылку. Текущий объект показан последним, предки ведут в каталоги.
- Блок 2 — каталог либо информация о выбранном файле.
- Блок 3 — действия, затем подготовленное файловое вложение, если оно есть. Внизу находятся clipboard и статус операции.
- Названия действий, приглашения, статусы и ошибки пишутся на английском; пользовательские имена сохраняются.

### Каталог

Список позволяет выбирать поддиректорию или файл. Первым пунктом на каждой странице показывается единая ссылка `📁 ..` с кликабельной иконкой папки — переход в родительский каталог; он не входит в пагинацию и счётчик, в корне полностью отсутствует. Под списком фиксированная отцентрированная панель: `↩️`, `◀️`, заблокированная позиция вида `1-10/33`, `▶️`, `🔄`. Активные иконки навигационной панели имеют зелёный стиль `success`; неактивные кнопки остаются без цветового стиля, на месте заблокированными; пустой каталог показывает `0-0/0`. В корне переход вверх заблокирован. Выбор файла открывает информацию о нём; вложение автоматически не загружается. Переход через крошки открывает соответствующий каталог.

### Файл

Показываются полный относительный путь `Path:` с форматированием code, размер и дата изменения. Текстовый предпросмотр доступен только для файлов размером не более 2 KiB (2048 байт) и содержит не более первых 50 строк. Если строк больше, сокращение отмечается отдельно от содержимого. Предпросмотр оформляется rich-блоком `pre`; по возможности указывается `language`. Для изображения показывается кешируемое превью. Под информацией о файле фиксированная отцентрированная панель: `↩️`, `◀️`, заблокированная позиция вида `7 / 15`, `▶️`, `🔄`. Галерея перебирает все доступные обычные файлы текущего каталога в порядке списка, пропуская подкаталоги; перехода по кругу нет. На границах стрелки заблокированы. Назад возвращает на страницу каталога с текущим файлом; Refresh пересчитывает состав галереи. Активные иконки навигационной панели зелёные (`success`), заблокированные остаются без цветового стиля. Стили ссылок и файловых действий не меняются. Панели действий и подтверждения тоже отцентрированы.

### Действия

| Действие | Каталог | Файл |
|---|---|---|
| `Upload` | Приглашение загрузить документ внутрь каталога с исходным именем | Приглашение заменить выбранный файл независимо от имени загруженного документа |
| `Download` | Собрать ZIP-архив каталога и встроить его документом | Встроить выбранный файл документом |
| `Delete` | Удалить каталог рекурсивно после подтверждения | Удалить файл после подтверждения |
| `Copy` | Запомнить путь каталога | Запомнить путь файла |
| `Paste` | Скопировать источник из clipboard внутрь каталога с его исходным именем | Заменить содержимое выбранного файла файлом из clipboard |

В файл можно вставить только файл. `Copy` запоминает путь, а не снимок содержимого: при `Paste` читается актуальный источник. Clipboard общий для пользователя в пределах одного бота, отображается как `Clipboard: 📄 wiki/report.md` либо `Clipboard: 📁 wiki/reports`.

### Подтверждения и совпадения имён

- `Delete` всегда требует подтверждения с точным путём и кнопками `Delete` / `Cancel`.
- Совпадение имени при `Upload` или `Paste` требует подтверждения до записи.
- Для файлов подтверждение разрешает замену содержимого.
- Для каталогов подтверждение разрешает рекурсивное слияние: новые объекты добавляются, совпадающие файлы заменяются, остальные файлы назначения сохраняются.
- При вставке файла прямо в выбранный файл назначение уже существует: замена также подтверждается. То же правило применяется к `Upload` выбранного файла.
- Одно подтверждение слияния охватывает весь выбранный каталог, а не отдельное подтверждение каждого вложенного файла.

### Вложения, кеш и Refresh

- В блоке действий показывается не более одного подготовленного документа.
- Повторный `Download` сначала удаляет прежнее вложение из rich-сообщения, затем заново читает файл либо собирает архив и загружает новый документ. Он не подменяется возвратом старого кешированного вложения.
- Подготовленные вложения и превью кешируются на время работы browse. Обычные перерисовки не должны повторно загружать неизменившееся изображение или документ.
- При переходе к другому объекту вложение предыдущего объекта убирается из видимого сообщения; его кеш может оставаться до конца сессии.
- `Refresh` обновляет список или сведения/предпросмотр/превью. Подготовленный документ остаётся снимком последнего `Download`, а не незаметно пересобирается.
- После изменения объекта через `Upload`, `Paste` или `Delete` связанные устаревшие превью и подготовленные документы сбрасываются; сведения обновляются.

### Один процесс на пользователя

- Для пары бот + пользователь допускается один активный browse, в том числе при вызовах из разных чатов этого бота.
- Новый `/browse` удаляет предыдущее сообщение и открывает указанную директорию либо корень, перенося clipboard и кеш.
- Старые callbacks не исполняются после смены сообщения. Нельзя считать старый адрес актуальным только из-за совпадения native ID.
- При длительной операции кнопки проводника блокируются. Внизу отображается текущая операция, например `Creating archive…`, `Uploading…`, `Copying…`.
- Новый `/browse` во время операции переносит её статус и блокировку в новое сообщение. Вторая операция параллельно не запускается. Исходная операция продолжает работать с ранее зафиксированными путями.
- Завершение фоновой работы обновляет только актуальное сообщение сессии, не воскрешает удалённое и не переводит новый экран на старый путь.

### Приглашения Upload

При нажатии `Upload` выдаётся отдельное приглашение ответить документом, аналогичное текущему `/upload PATH`. В момент нажатия фиксируются путь и режим: загрузка внутрь каталога либо замена конкретного файла. Последующая навигация не меняет назначение приглашения.

Используются текущие ограничения приглашений: тот же бот, пользователь, чат и тема; только допустимый документ в ответ на подлинное приглашение; повторная проверка роли; одна успешная загрузка; срок один час; повтор после неуспешной попытки; потеря приглашений после перезапуска. Для каталогов имя поступает из документа и проверяется как одно имя файла, а не произвольный путь.

## Предлагаемые детали исполнителя

Эти параметры и правила не были отдельно заданы пользователем; они предлагаются для целостного плана.

### Отображение и срок работы

- Папки первыми, затем файлы; стабильная сортировка по имени. По 10 элементов на страницу. Пустой результат имеет явное состояние `Directory is empty.`.
- Текст для предпросмотра должен быть валидным UTF-8 без признаков бинарного содержимого. Лимит размера проверяется по байтам всего файла до декодирования; число строк учитывает LF и CRLF. Имена и содержимое передаются как данные, а не исполняемая разметка.
- Для `language` сначала использовать известное расширение/имя файла, затем при необходимости очевидный shebang. Если язык не определён уверенно, поле опускается. Собственный универсальный классификатор содержимого и модельный запрос не нужны. Точная таблица языков остаётся исполнителю плана.
- Форматы и размеры изображений проверяются до подготовки превью. Неподдерживаемое изображение остаётся доступным как документ. Конкретный способ генерации уменьшенного превью выбирается в плане после проверки зависимостей; исходный файл не меняется.
- Сессия живёт один час без активности; новый `/browse` продлевает её с переносом кеша. Перезапуск завершает сессии, clipboard и локальные кеши. Это оперативное состояние, не постоянная пользовательская настройка.
- Кеш находится вне дерева, доступного проводнику, чтобы не попадать в архивы и копии. У него есть ограничение объёма, удаление вытесненных элементов и уборка после завершения/перезапуска. Конкретные пределы и механизм уборки определяются в плане.
- Переоткрытие того же неизменившегося объекта может использовать его кеш. Ключ превью учитывает путь и версию файла; кешированные документы остаются снимками, пока не запрошен новый `Download`.
- Новый `/browse` закрывает старые приглашения и подтверждения. Удаление старого Telegram-сообщения само по себе не считается аннулированием его действий: это делает контроллер.

### Запись и файловые границы

- Команда и каждое действие требуют текущую роль `admin` или `owner` у этого бота. Сессия принадлежит вызвавшему пользователю. Потеря роли немедленно запрещает действия, даже при существующем кеше.
- Использовать ограничения `BotFiles`: только файлы этого бота, без traversal, symlinks и защищённых скрытых компонентов; `.temp` доступна администратору. Нельзя возвращать защищённые пути в списках, архивах или рекурсивных копиях.
- Отсутствующий каталог ведёт в корень. Ошибка доступа, запрещённый путь и ошибка чтения не маскируются под отсутствие. Если `dir` указывает на обычный файл, открывается корень: аргумент команды предназначен для каталога.
- Корень можно просматривать, скачивать и использовать как назначение Upload/Paste. `Delete` и `Copy` корня отключены.
- Действия используют серверные записи с непрозрачными короткими ключами; длинные пути не помещаются в callback_data и не принимаются из кнопок как полномочия.
- Перед записью проверяются источник, назначение, права и актуальность подтверждения. При изменении подтверждаемого объекта или состава конфликтов требуется новое подтверждение.
- Вставка объекта в себя и каталога в собственного потомка запрещена. Конфликт типов файл/каталог отклоняется до записи: слияние не означает удаление каталога ради файла или наоборот.
- Рекурсивные копии и архивы обходят только доступные объекты; защищённые и символьные ссылки исключаются без следования за ними. Сохраняются пустые доступные каталоги. ZIP содержит относительные пути без абсолютных имён и `..`; имя корневого архива не раскрывает путь машины.
- Файл заменяется через подготовку и атомарную замену, чтобы ошибка чтения/загрузки не оставляла усечённое назначение. Слияние каталога не обещает единую транзакцию всего дерева; при частичной ошибке перечисляется итог, а операция не переигрывается автоматически.
- Если назначение Upload совпало, загруженные данные удерживаются временно до подтверждения; отмена не меняет файловую систему. При занятом browse документ не начинает параллельную файловую операцию.
- Сетевые ошибки с неизвестным результатом не приводят к автоматическому повтору публикации или записи. Если старое сообщение не удалось удалить, его обработчики всё равно аннулируются; частичный результат явно отражается пользователю.

## Проверенные основы и ограничения реализации

В исследованном `origin/main`:

- [Файловые команды](../../src/commands/files.mjs) уже используют `BotFiles`; `/ls` просто соединяет имена строками.
- [Роутер команд](../../src/commands/router.mjs), [ответы](../../src/commands/replies.mjs) и [приглашения](../../src/commands/uploads.mjs) поддерживают обычные/эфемерные ответы и одноразовые загрузки. Для browse потребуются расширения, включая фиксированный каталог назначения и продолжение после подтверждения.
- [Контроллер](../../src/controller.mjs) сейчас отклоняет эфемерные callbacks; обычные agent-кнопки зависят от агента. Browse нужен собственный обработчик контроллерных сессий до этих маршрутов.
- [Подготовка медиа](../../src/files/media.mjs) обрабатывает документы и изображения внутри rich-блоков и поддерживает multipart. [Приватное редактирование](../../src/ephemeral/messages.mjs) уже вызывает native rich edit, но интерактивные приватные кнопки в текущем агентском API запрещены.
- [Widget media](../../src/widgets/media.mjs) содержит пример кеша по версии файла и native `file_id`. Это полезный код для изучения, но browse не обязан становиться агентским sandbox-widget.

По [Telegram Bot API](https://core.telegram.org/bots/api#inputrichblockdocument) документ допустим как rich-блок. [editEphemeralMessageText](https://core.telegram.org/bots/api#editephemeralmessagetext) принимает новое rich-содержимое и возвращает `True`, а не полный `Message`. Поэтому извлечение нового `file_id` из ответа на такое редактирование нельзя считать готовым механизмом кеширования; план должен выбрать проверяемый способ повторного использования файлов без скрытой публикации в других чатах.

Кеш может хранить подготовленные локальные данные и доступные подтверждённые native file ID. Не обещать повторное использование неизвестного ID. Возможность добавлять новое вложение/превью редактированием эфемерного rich-сообщения и сохранять их при последующих перерисовках требует узкой живой проверки на Android. Документация API и fake-transport тесты не заменяют эту проверку.

Telegram [заявляет автоматическое распознавание языка для code-блоков](https://telegram.org/blog/similar-channels#code-highlighting-in-messages). В [InputRichBlockPreformatted](https://core.telegram.org/bots/api#inputrichblockpreformatted) поле `language` необязательно; API не обещает возврат определённого языка боту и не описывает отдельно автоматическое распознавание в эфемерном rich `pre`. Поэтому при известном языке предлагается указывать его явно, а поведение без `language` проверить на целевом клиенте.

## Что должно войти в план реализации

1. Проверка native rich edit + новое вложение + превью + callbacks в эфемерном Android-сообщении, включая поведение кеша без возвращённого `Message`.
2. Контроллерные сессии, маршрутизация callbacks, смена сообщения, clipboard, кеш, сериализация действий и обработка неопределённого результата доставки.
3. Безопасные файловые сведения, пагинация, предпросмотры, ZIP, копирование и подтверждаемые изменения.
4. Привязанные Upload-приглашения, подтверждение конфликтов и обновление текущего экрана.
5. Регистрация `/browse`, текущая английская справка и обновления [команд](../commands.md), [эфемерных взаимодействий](../ephemeral.md), [хранилища](../storage.md) и затронутых ограничений [безопасности](../security.md).
6. Регрессии существующих файловых команд и проверки новых маршрутов: роли, пользователь/бот/тема, старые callbacks и приглашения, пути/симлинки, конфликты, слияние, само-копирование, смена сообщения во время работы, свежий повторный Download, очистка кеша и отказ доставки без публичного fallback.

Числовые лимиты, зависимости для ZIP/изображений и конкретные внутренние интерфейсы оставлены исполнителю плана. Коммит, merge, push и запуск живой проверки не входят автоматически в этот документ: нужны соответствующие инструкции пользователя и конкретный разрешённый тестовый маршрут.
