### Desktop layout depends on the first page

The user observed tall thumbnail/text blocks in the raw initial-page control, versus compact rows without thumbnails after the earlier live-agent drum. Source inspection of Telegram Desktop at commit `b16daff6df63e8a812bc2b52a04ff243f67a7d3f` explains this distinction: [validateExistingInlineRows](https://github.com/telegramdesktop/tdesktop/blob/b16daff6df63e8a812bc2b52a04ff243f67a7d3f/Telegram/SourceFiles/inline_bots/inline_results_inner.cpp#L589-L605) chooses `_inlineWithThumb` while the mosaic is empty. Later appended pages reuse the existing choice. [hasThumbDisplay](https://github.com/telegramdesktop/tdesktop/blob/b16daff6df63e8a812bc2b52a04ff243f67a7d3f/Telegram/SourceFiles/inline_bots/inline_bot_result.cpp#L369-L379) recognizes thumbnails, photos, contacts and locations; the raw first page has these, while title-only drum articles do not. [Article::countHeight](https://github.com/telegramdesktop/tdesktop/blob/b16daff6df63e8a812bc2b52a04ff243f67a7d3f/Telegram/SourceFiles/inline_bots/inline_bot_layout_internal.cpp#L1481-L1494) gives thumbnail-mode articles a minimum thumbnail height. No dedicated layout flag was sent by either test runner.

This source mechanism matches the observed row-height difference; the installed client version is unrecorded. It also offers a specific explanation to test for earlier apparently missing cached photos/stickers: [list-mode layout conversion](https://github.com/telegramdesktop/tdesktop/blob/b16daff6df63e8a812bc2b52a04ff243f67a7d3f/Telegram/SourceFiles/inline_bots/inline_bot_layout_item.cpp#L100-L110) renders photo/sticker/GIF results as articles. Without the thumbnail column or text, such a row can collapse to minimal padding. The paired live control below reproduces this photo-visibility failure with identical final results and only the first-page thumbnail fields changed. Production policy is unchanged. Existing compact-drum row-count measurements do not establish prefetch behavior for a drum starting in thumbnail mode.
