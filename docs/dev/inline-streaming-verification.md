## Live acceptance procedure

The opt-in runner is `test/manual/inline-streaming.mjs`. It requires the designated test-bot configuration (`controllerActive:false`) and a fresh ignored state directory. It takes the existing `inline-calibration.lock` beside that configuration. It creates only three quiet PNG buffers in the designated owner's private chat, confines inline processing to that user, and never joins/leaves groups or changes bot command lists. It stops after at most 30 minutes, on a stop file, or the owner's private `/stream stop` command. Cleanup deletes only the three buffers and restores the preceding allowed-update inventory; selected inline publications remain untouched.

```powershell
node test/manual/inline-streaming.mjs --config PRIVATE_TEST_CONFIG --state-dir .runtime-check/streaming-RUN --duration-seconds 1800
```

After the ready event, invoke the designated bot with a new query each time. Wait at least two seconds before scrolling to submit:

1. `stream photos`: expect the intermediate report, working rows while waiting, then blue/red/green photos approximately ten seconds apart. Confirm photos remain visible across the text/photo transitions and can be selected/sent. No artificial working row is required if a photo is ready before its page is requested.
2. `stream ready`: all portions are queued immediately; expect report followed by photos without a forced working pause.
3. `stream late-close`: all three photos arrive with continuation; completion occurs ten seconds after the last photo. A further page request should close without another Work complete card.
4. `stream status`: an intermediate report with a controller arrow, then a terminal report without one. Selecting a report must send only `✖️`.
5. During `stream photos`, change the query before later portions arrive. Old work should be rejected without publishing old results into the replacement request.

Record the client/version and observed behavior. Inspect events.jsonl and cleanup.json in the fresh state directory; do not copy tokens, user IDs, buffer IDs or private request contents into tracked documentation. Desktop exercised all five scenarios above; Android exercised incremental photo delivery/selection and row layout. The other four cases were not separately repeated on Android. Client build versions and iOS were not checked. The probe has no model calls and does not prove autonomous agent orchestration.
